• Independent attack review: six exploits found and fixed. Three attackers worked from the code alone, each with one goal: read without paying, break a cap, and find anything hidden-dependent outside costed readings. Each fix has a regression check.
    • No-op steps. speed_step(s = 1) reproduced the nominal setpoint and returned 6-21 nominal readings for 4 units (0.31 per reading). Experiments now reject abs(s - 1) < 0.05 and theta > 0.95.
    • Huge integers. magnitude: 10**400 raised an uncaught error: the call went untraced, the strike rule was skipped and raw text reached the agent. It is now a field-level rejection, and any unexpected error becomes a traced E_INTERNAL.
    • Reserved marker keys. Agent-sent {"__too_large__": 1} dodged the call cap and strikes. The oversize verdict is now decided from the real arguments and recorded in the trace, and every call counts toward the cap.
    • Oversized tool names. A 3.5 MB tool name was logged verbatim. Names are now truncated to 40 characters.
    • Timing. run_experiment latency revealed the true plant's solver iterations (p = 5e-4 over real MCP). Costed calls are now padded to a constant 50 ms (no detectable difference after the fix: p of about 0.3), and stuck sensors always draw their noise.
    Held under attack: concurrency (66 simultaneous calls over 2 sessions spent exactly 40), double submit, the simulate cap, the time cap, and every free tool and error message (byte-identical across hidden fault sets over 3,017 calls).
  • Decision needed: the topology reveals the tier, and so the exact fault counts. From the free get_topology, junction count, pump count and loop count identify the tier in about 94% of plants. Each tier has fixed fault counts (easy 1, medium 2+1, hard 3+2), so the agent can infer how many faults to look for. That contradicts the "no counts disclosed" default. Options: state the counts per tier openly in the manual (simple and honest); or draw fault counts independently of plant size.
  • F10 discrimination, measured over the full fault ranges (for Step 6 calibration). Hypothesis magnitudes are drawn uniformly from each fault type's range:
    • Stuck valve vs fouling and pump wear vs system resistance always separate, by 8 to 64 sigma.
    • Sensor bias vs fouling separates by exactly the bias, so the plan's 4-10 sigma bias range puts about a sixth of biases below the 5 sigma single-reading criterion. That is a plan inconsistency, not a physics problem.
    • Leak vs flow-meter bias is the weak pair: about 3 sigma on the best single sensor, 65% at 5 sigma when every returned sensor is combined.
    • Static-test pressure sag, worst over every leak position, is 0.09 / 0.56 / 1.42 sigma at leak 0.02 / 0.05 / 0.08, against the plan's 0.5 sigma.
    These are dials (bias and leak ranges, flow-meter noise) for the Step 6 calibration, not decisions now. The manual documents all of it, including that leak vs meter bias needs combined or repeated evidence.
  • Decision needed: where judged runs execute (F14).
    • Every container-isolation probe passes: no truth, state, trace, simulator code or seed is visible from the agent's container; a full 1-65535 port scan finds only the MCP port; no admin or score route exists; the agent image's 65 MB of layers contain no simulator strings.
    • With Harbor's public network, the agent can reach the internet, and so could fetch the public repository and regenerate plants.
    • Harbor's no-network and allowlist modes need nftables support that Docker Desktop's kernel lacks, so this Mac cannot block egress.
    • A Linux Docker host with a static allowlist (model API only, plus npm unless OpenCode is baked into the agent image) is the candidate. It is untested; OpenCode's disable_web_search is a partial extra guard.
  • Decision needed: two disclosures in the manual.
    • The manual tells the agent that every physical fault alone degrades the KPI by at least 5%. That is tied to the open eligibility choice from Step 2, and it lets an agent rule out small faults.
    • The plan's confound row "high power at normal flow: wear vs fouling" does not hold here: wear lowered the pump's power in 55 of 55 cases. The manual says "low pump flow, changed pump power" instead; the separating experiment (a speed sweep) is unchanged.
  • Defaults to confirm:
    • the 150-call cap excludes simulate, which has its own cap of 300;
    • the fourth invalid submit finalizes the episode with an empty submission;
    • stuck sensors read an exact constant (open since Step 2);
    • tier and fault counts are not disclosed.
  • Architecture. mcp 2.3 silently ignores unknown arguments and runs sync tools in worker threads, so a thin MCPServer subclass passes raw arguments to one locked episode core. Every call, valid or not, is validated, traced and counted the same way; 60 concurrent reads at budget 40 accept exactly 40 units.

    • The malformed-HTTP fuzz only reached the transport: every reply was 400, before any tool code ran. The 10,000-call fuzz exercises the tool code directly.
    • The placeholder reward stands in until Step 4, and the placeholder oracle until Step 5.
