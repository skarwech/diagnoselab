Findings and open decisions

  • F24 fails: the frontier agent is too good for the target band in every configuration tried. Kimi K3.1 Pro via opencode scores 0.82 to 0.88 normalised overall (target 0.35-0.65), across 105 episodes. Harness friction is negligible (11 rejected calls of 6,610, no format failures), so this measures the agent. The human audit was skipped by your decision.
  • The agent diagnoses about as well as the oracle. Agent D vs oracle D sits on the diagonal in every configuration. Scores are normalised by the oracle, so any dial that makes the plant harder for both leaves the ratio where it was: subtler faults (0.85 overall) and half the flow meters (0.88) both confirmed it. Neither is kept.
  • Only budget pressure moved the agent. On the same 10 medium/hard instances, cutting B from 40 to 26 lowered the agent from 0.93 to 0.76: it now sometimes commits to the wrong explanation (scores split between about 1.0 and collapses). Overspending alone costs at most about 0.1, so a dial must make the agent miss faults to matter.
  • Configuration frozen at B = 40 (your decision). B = 26 was the only setting that moved the agent, but it broke the oracle's medium F19 target on the official seeds (0.87) and F5 on hard (66.5%). At B = 40 the oracle meets its D targets and the Step 2-5 results are exactly the approved ones. The agent scores 0.85 overall there (0.71 / 0.95 / 0.90 on 5 seeds per tier, so wide intervals). Frozen configuration hash: dc9bbc81fc21; test seeds are reported once, at Step 7.
  • Where a real gap could come from (outside the plan's dials). A stronger reference than this oracle, a different scoring reference, or a task whose difficulty lies in decisions the agent gets wrong under pressure (budget-limited sequential choices) rather than in harder physics. These change the design and are your call.
  • Built this step and kept whatever you decide: per-seed Harbor task generation with the R_oracle >= 0.5 acceptance rule; a configuration hash in the cache and every score (finalize refuses a stale cache); the budget set in one place and read by the oracle; F20 checked from real Harbor results; a pilot friction/score report; make pilot.
  • Cost: about 61M input tokens (mostly cached) and 0.72M output across 105 agent episodes. Verda does not report prices through the API; check the console against your $50 cap.
